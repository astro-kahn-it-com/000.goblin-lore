**Feature ID:** `FEAT-001.03` **Parent Epic:** [EPIC-001] SOVEREIGN FOUNDATIONS **Governing

---

### **I. FUNCTIONAL MANDATE**

**Strategic Goal** This feature implements and proves the deterministic build ordering guarantee
underlying the entire Initiative's Sovereign Objective: `goblin-config` builds first,
`goblin-bible`'s `compile.ts` runs second and consumes `goblin-config`'s rules, and `worker-sower`'s
Terminal OS boot sequence only proceeds if a valid, freshly compiled `bible-state.json` exists. This
is proven via a clean-room script, not assumed from documentation.

**Business Value**

- **Eliminates order-of-operations bugs:** A `worker-sower` boot against a stale or missing compiled
  corpus is a class of bug this feature makes structurally impossible, not just unlikely.
- **Enables trustworthy CI gating:** Every downstream Milestone's audit protocols (MS-02 through
  MS-06) assume a correctly-ordered build as their starting condition — this feature is what makes
  that assumption safe to make.
- **Surfaces build-cache staleness immediately:** The clean-room script explicitly clears caches
  before each ordered build, preventing a false "pass" caused by npm serving a stale cached artifact
  instead of a genuinely fresh compile.

**Failure Criteria (Rollback Plan)**

- **Immediate Rollback:** If the ordered build script (`npm run build:ordered`) takes more than 180
  seconds end-to-end on CI hardware — indicating the tiering itself has introduced unacceptable
  serialization overhead.
- **Suspension:** If any of ten consecutive clean-room runs produces a different success/failure
  result or a different build-order log than the others — the non-determinism must be root-caused
  before this feature is considered stable.
- **Kill Switch:** If a genuine circular dependency is discovered between `goblin-config`,
  `goblin-bible`, and `worker-sower` that cannot be resolved by reordering — escalate to Lead
  Architect for architectural restructuring within 24 hours.

---

### **II. TECHNICAL CONSTRAINTS & REQUIREMENTS**

- **Ordering Guarantee:** The build script must not rely on npm's default workspace parallelism; it
  must explicitly sequence `goblin-config` → `goblin-bible` (`compile.ts`) → `worker-sower` (boot
  readiness check only, not a full boot).
- **Cache Independence:** The clean-room proof script clears `node_modules` and any build cache
  directories before every run, so a "pass" can never be attributed to stale cached output.
- **Failure Propagation:** If `goblin-config`'s build fails, the script must halt immediately and
  not attempt `goblin-bible`'s compile step — a partial, out-of-order execution must never silently
  continue.
- **Determinism Proof:** The script supports a `--repeat N` flag re-running the full ordered
  sequence N times and diffing the build-order log across runs, not just the final exit code.
