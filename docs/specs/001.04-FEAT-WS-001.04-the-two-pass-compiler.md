### **I. FUNCTIONAL MANDATE**

**Strategic Goal** This feature implements the two-pass validation core of `compile.ts` — Pass 1
strips YAML frontmatter via `gray-matter` and validates every corpus file against strict, per-type
Zod schemas; Pass 2 verifies every relational pointer (`owner`, `participants`, `location`,
`linked_grievances`, `linked_possessions`) resolves to an existing, non-retired file. A violation in
either pass produces a hard fail with an actionable, file-and-field-specific error — the compiler
never silently accepts malformed or relationally broken corpus content.

**Business Value**

- **Makes corruption structurally impossible to compile:** A possession claiming ownership by a
  nonexistent character cannot produce a `bible-state.json` — the corruption is caught at the
  source, not discovered downstream in a duel resolution.
- **Protects every downstream psychological calculation:** The Individuation Multiplier, the
  six-outcome duel taxonomy, and the selection lottery all trust the compiled state implicitly —
  this feature is what makes that trust warranted.
- **Turns corpus authoring mistakes into immediate, specific feedback:** A showrunner editing a
  grievance file gets a precise error pointing at the exact broken field, not a mysterious
  downstream simulation anomaly weeks later.

**Failure Criteria (Rollback Plan)**

- **Immediate Rollback:** If Pass 1 + Pass 2 combined compile time exceeds 2.5ms per file (per the
  governing Initiative's Compute Budgets) at the current 40+ grievance corpus scale.
- **Suspension:** If any relational field type is discovered to be exempt from Pass 2 checking (an
  incomplete pointer-type inventory) — pause further corpus growth until the gap is closed, since
  new content could be silently relying on the unchecked field.
- **Kill Switch:** If a corpus file is found that passes compilation despite containing a genuinely
  broken relational pointer (a Pass 2 escape) — treat as a Sev-1 data-integrity incident; escalate
  to Lead Architect within 4 hours, as this directly contradicts the Sovereign Objective's 100%
  relational integrity guarantee.

---

### **II. TECHNICAL CONSTRAINTS & REQUIREMENTS**

- **Pass 1 Scope:** Strips frontmatter via `gray-matter`; validates against exactly four schema
  types — character, grievance, location, possession — with zero tolerance for type mismatches (a
  string where a number is expected throws a fatal, file-identified error).
- **Pass 2 Scope:** Exhaustively checks every relational field across all four schema types against
  an in-memory index of all active (non-retired) file IDs, built once per compile run for O(1)
  lookup rather than repeated linear scans.
- **Error Specificity:** Every hard-fail error message must include the offending file's path and
  the specific field name — a generic "compilation failed" message is not acceptable output.
- **Retirement Awareness:** Pass 2 excludes `_retired/` files from the valid-pointer index by
  default, unless a pointer is itself explicitly flagged as an intentional historical reference.
