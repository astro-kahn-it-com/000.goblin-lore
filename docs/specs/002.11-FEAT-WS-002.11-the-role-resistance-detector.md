### **I. FUNCTIONAL MANDATE**

**Strategic Goal** This feature implements the logic comparing a candidate grievance's participants
and category against each involved character's `relationship_type_defaults` — specifically the
`given` versus `received` role framing — to correctly identify when a character is actively cast
against a role they resist. The canonical example: Spleen's `received: caretaker_resented` dynamic
from Bog, where Spleen's individuation arc is defined by resisting exactly that imposed role.

**Business Value**

- **Is the actual mechanical substance behind the project's entire Jungian premise:** Every
  governing document across this project asserts individuation as a thematic spine, but without this
  feature, that assertion has no computable referent — this is the code that makes "Spleen resists
  being cared for" a checkable fact rather than a narrative aspiration.
- **Produces a falsifiable, testable definition of "resistance":** Rather than leaving individuation
  as a subjective interpretive lens applied inconsistently across characters, this feature forces a
  concrete, documented rule set — resistance either detects correctly against the documented truth
  table or it doesn't.
- **Feeds the Individuation Multiplier with a real, checkable signal:** `FEAT-002.12`'s multiplier
  application is only as meaningful as this Feature's detection accuracy — a false positive or false
  negative here silently distorts every downstream selection-lottery weighting decision.

**Failure Criteria (Rollback Plan)**

- **Immediate Rollback:** If the detector produces a different resistance-detection result for the
  same character/grievance pair across two identical calls — the detection logic must itself be
  deterministic and pure.
- **Suspension:** If the definition of "resistance" is found to require a judgment call not
  resolvable from the documented `relationship_type_defaults` truth table alone (an ambiguous case
  the schema doesn't cover) — pause and extend the schema/truth table explicitly rather than
  hardcoding an ad hoc resolution.
- **Kill Switch:** If the detector is found producing a resistance-positive result for a
  character/relationship combination that has no basis in the character's documented
  `relationship_type_defaults` at all (a fabricated detection) — escalate to Lead Architect within
  24 hours, since this would mean the multiplier is influencing narrative selection based on
  non-existent psychological grounding.

---

### **II. TECHNICAL CONSTRAINTS & REQUIREMENTS**

- **Detection Rule:** A character is considered "resisting" a role in a candidate grievance if the
  grievance's `category` matches a `received` role in that character's `relationship_type_defaults`
  for one of the grievance's other `participants`, AND that role is documented (via a per-character
  truth table entry) as one the character's individuation arc pushes against.
- **Truth Table Source:** The per-character list of resisted roles is explicit, hand-authored data
  (not inferred from stats or heuristics), stored alongside each character's corpus file and
  validated by `compile.ts`'s Pass 1 schema check.
- **Purity:** The detector is a pure function of the compiled corpus state — given the same
  grievance and character data, it always returns the same result, with no reliance on
  cycle-specific mutable state.
