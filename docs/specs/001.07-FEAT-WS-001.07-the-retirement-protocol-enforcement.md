### **I. FUNCTIONAL MANDATE**

**Strategic Goal** This feature implements the `_retired/` directory handling within `compile.ts`,
correctly excluding retired files from the active Stage 3 selection lottery candidate pool while
still validating that no _active_ corpus file references a retired one without an explicit, logged
exception. This preserves the corpus's full historical audit trail without allowing dead plots or
resolved grievances to silently pollute live narrative generation.

**Business Value**

- **Prevents dead-plot resurfacing:** A resolved grievance or destroyed possession can never be
  accidentally re-selected by the lottery, since retirement is enforced at the index-construction
  level, not by convention.
- **Preserves historical auditability:** Retired files remain on disk with their one-line retirement
  explanation, giving future showrunners (and the MS-06 Reconciliation Protocol) a complete record
  of what happened and why, rather than silently deleted history.
- **Distinguishes accidental orphaning from intentional callback:** A grievance actively referencing
  a retired file without an explicit exception flag is caught as a likely authoring mistake, while a
  deliberate historical callback is permitted and logged.

**Failure Criteria (Rollback Plan)**

- **Immediate Rollback:** If a retired file is found present in the Stage 3 lottery candidate pool
  at any point — this is a direct contradiction of the feature's core guarantee and blocks release
  immediately.
- **Suspension:** If more than 10% of a sample of active-corpus-to-retired-file references lack the
  explicit exception flag, suggesting the exception mechanism is being bypassed rather than
  deliberately used — pause and review authoring practices before continuing.
- **Kill Switch:** If retiring a file is found to silently break Pass 2 relational integrity for an
  _active_ file that depended on it without an exception — escalate to Lead Architect within 24
  hours, since this indicates the retirement protocol and the relational-integrity compiler are not
  correctly coordinated.

---

### **II. TECHNICAL CONSTRAINTS & REQUIREMENTS**

- **Lottery Exclusion:** The relational index built in `FEAT-001.05` explicitly omits `_retired/`
  files from the pool `worker-sower`'s Stage 3 selection reads from, at construction time.
- **Reference Validation:** Pass 2 (from `FEAT-001.04`) checks whether any active file's relational
  pointer targets a retired file; if so, it requires an explicit
  `intentional_historical_reference: true` flag on that specific pointer, hard-failing otherwise.
- **Retirement Metadata:** A retired file's frontmatter must include a one-line `retirement_reason`
  field, with Pass 1 validation confirming this field is present and non-empty for every file under
  `_retired/`.
