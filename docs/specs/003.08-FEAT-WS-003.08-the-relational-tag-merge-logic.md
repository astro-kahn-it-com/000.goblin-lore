### **I. FUNCTIONAL MANDATE**

**Strategic Goal** This feature confirms and permanently tests that explicit `[[grievance_id]]` tags
a showrunner inserts into an outline are correctly unioned with engine-seeded `linked_grievances` —
via the existing `Array.from(new Set([...seeded, ...explicitTags]))` pattern already implemented in
`extract.ts` — with zero duplicate entries and zero loss of either source's contributions. This
feature also formally documents the known limitation this merge approach carries: it is
additive-only, with no mechanism for a showrunner to remove a seeded relational link.

**Business Value**

- **Validates a subtle but important piece of the extraction pipeline's design:** The union-based
  merge is a deliberate choice (favoring safety — never silently dropping an engine-seeded
  relationship — over flexibility), and this feature is what confirms that choice actually behaves
  as intended rather than being an untested assumption.
- **Turns a known limitation into documented, expected behavior rather than a surprise:** A
  showrunner who discovers they can't remove a seeded relational tag should find that documented and
  explained, not encounter it as an unexplained bug during real production use.
- **Protects data integrity in the specific case most likely to be exercised in real Hybrid
  Authoring sessions:** Adding a `[[tag]]` to note a new narrative connection is a realistic,
  expected showrunner action — this feature ensures that exact common action is solid.

**Failure Criteria (Rollback Plan)**

- **Immediate Rollback:** If a merge test shows either a duplicate entry or a lost contribution
  (from either the seeded or explicit source) in the resulting `linked_grievances` array — this is a
  direct correctness violation.
- **Suspension:** If real showrunner usage (once MS-05 is live) reveals the additive-only limitation
  is a genuine, frequently-encountered pain point rather than a rare edge case — pause and
  reconsider whether a removal mechanism should be prioritized as a follow-on feature.
- **Kill Switch:** None — this Feature validates existing, already-implemented logic; a discovered
  defect is a fixable bug in `extract.ts`, not an unrecoverable state.

---

### **II. TECHNICAL CONSTRAINTS & REQUIREMENTS**

- **Union Correctness:** Test scenarios cover all four combination cases — seeded-only (no explicit
  tags), explicit-only (no seeded relations), overlapping (the same grievance ID present in both),
  and fully disjoint (different IDs in each) — confirming the resulting array is correct in every
  case.
- **Documented Limitation:** `docs/testing/round-trip-catalog.md` explicitly states the
  additive-only nature of the merge, with a worked example showing an attempted "removal" (deleting
  a `[[tag]]` from the outline) does NOT remove the corresponding entry from `linked_grievances`.
- **No Silent Behavior Change:** This Feature validates existing behavior; it does not modify
  `extract.ts`'s merge logic — any desire to change the behavior (e.g., adding removal support) is
  explicitly out of scope and would be a separate, future feature.
